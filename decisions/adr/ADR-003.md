# ADR-003: The Dashboard Ships as a Web Container by Default

**Date:** 2026-10
**Status:** Accepted
**Deciders:** raisga core team

## Context

p4n4-dashboard started as a Flutter app for desktop and mobile. Every operator had to
install it, every client needed a per-platform build, and nothing in `p4n4 up` started a
UI. Flutter can also target the browser, but a browser brings constraints a native app
doesn't have:

- **CORS:** p4n4-api, Ollama and Letta don't send CORS headers for the dashboard's origin,
  so a page calling them directly fails.
- **`localhost` is the viewer's machine:** on a phone, the stacks are on the host that
  served the page, not on `localhost`.
- **Offline LANs:** by default Flutter web loads CanvasKit from Google's CDN, but p4n4
  targets offline networks and Raspberry Pis.
- **Branding:** brands are applied at build time, and one client's build must never
  contain another's branding.

## Decision

The dashboard is a p4n4 layer (`dashboard`, after `edge` in the dependency order) whose
default form is one container, `p4n4-dashboard`, on port 8088:

1. **Same-origin proxy.** nginx serves the web build and proxies `/api/`, `/ollama/` and
   `/letta/` to fixed upstreams from environment variables. The app calls those paths, so
   CORS never comes up. Grafana and cameras load directly as `<iframe>` / `<img>`, which
   CORS doesn't cover. Grafana must allow framing.
2. **Runtime config, build-time brand.** Addresses come from `/config.json`, rendered from
   env vars at container start, so one image works on every host. When a value is empty,
   the app uses the host that served the page. The brand is baked in at build time
   (`BRAND` build arg, or `make image THEME=<project>`). The public image carries only the
   p4n4 brand; client images go to private registries.
3. **Offline.** CanvasKit and fonts are bundled (`--no-web-resources-cdn`), so the page
   makes no requests outside the LAN.
4. **Native stays.** The same code base builds Android, iOS, macOS, Windows and Linux apps
   as CI release artifacts, not containers. Platform-specific code sits behind conditional
   imports (`lib/platform/`), and `lib/` has no `dart:io`.
5. **JavaScript, not Wasm.** Multi-threaded Wasm (skwasm) needs cross-origin isolation
   (COOP/COEP), which would block the Grafana iframe and camera images unless they're
   proxied too. Revisit once everything is same-origin.

## Consequences

**Positive:**

- `p4n4 init --layer all && p4n4 up` gives a UI at `http://<host>:8088` on any device,
  with nothing to install.
- One image runs on amd64 and arm64. Its Flutter build runs once on the builder's
  platform, and only the nginx stage is per-architecture.
- Dev and production use the same paths: `web_dev_config.yaml` mirrors the nginx routes
  for `flutter run`.

**Negative:**

- A web service is easier to reach than an installed app. The dashboard signs in with
  p4n4-api accounts (added after this decision), but it falls back to a role picker if
  the API runs with auth off, so keep auth on and bind the container to a trusted
  interface.
- p4n4-api v0.1 runs on the host, so the container reaches it through
  `host.docker.internal`. Docker's DNS doesn't serve that name, so the image's entrypoint
  maps it to its `/etc/hosts` address. Containerizing the API removes this.
- Behind HTTPS, browsers block the `http://` Grafana iframe and camera images (mixed
  content), so they'll need proxying too.
- On web, Ollama replies arrive all at once, because `package:http` buffers browser
  responses.
